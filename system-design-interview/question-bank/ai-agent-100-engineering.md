## 定位与优先级

- **P0 必答：** 核心机制、授权边界、业务正确性和基本失败处理。

## 通用答题方法

先说明用户目标、成功标准、非目标和允许的动作，再展开下面六步：

1. **约束：** 明确延迟、任务时长、预算、数据时效、租户与风险等级。
2. **规模：** 从请求量推导模型调用、Token、工具调用、并发和存储增长。
3. **状态：** 区分业务权威事实、执行记录、生成结果、记忆与检索索引。
4. **主链路：** 说明同步承诺、异步步骤、授权检查、验证与完成条件。
5. **失败：** 处理超时、未知结果、重复、断线、取消和依赖失效。
6. **取舍：** 用质量、成本、延迟和恢复指标验证方案，给出演进条件。

业务系统保存订单、权限和账户等事实；任务存储保存执行进度；知识索引与缓存是派生数据。模型输出和自然语言记忆不能替代这些权威状态。

容量估算应声明统计窗口和假设，不把平均值当作峰值保证：

```text
模型调用率 ≈ 任务到达率 × 每任务平均模型调用数（包含重试）
输入/输出 Token 速率 = 模型调用率 × 对应平均 Token 数
执行中任务数 ≈ 稳态任务到达率 × 平均执行时间
工具压力 = 任务到达率 × 每任务工具调用数（包含扇出与重试）
```

这些是初始估算。容量验证还需覆盖长输入、长输出、突发、慢依赖、租户热点和恢复流量；预算覆盖模型、Embedding、Rerank、工具、存储与评测。

## 练习指南

### 候选人训练

专项题按“结论、理由、适用边界”回答，再处理一次约束变化。核心案例先建立基线，只画必要边界、状态和主要依赖，然后处理故障注入。

每轮记录一个可验证改进动作，例如“下次先定义工具结果未知状态”，并在同一案例的变体中验证。不要只记录“继续熟悉 RAG”这类无法观察的目标。

### 面试官评估

| 观察点 | 可接受表现 | 深入表现 |
| --- | --- | --- |
| 目标与约束 | 问出会改变方案的条件 | 排序质量、延迟、预算与风险 |
| 权限与事实 | 区分模型建议和业务授权 | 说明执行前检查及事实核验 |
| 主链路 | 描述检索、模型、工具与状态 | 说明同步承诺及结果未知状态 |
| 失败恢复 | 回应具体故障 | 给出执行权、幂等、对账与人工边界 |
| 验证与演进 | 说明如何测质量与性能 | 给出切片、发布门禁与演进条件 |

追问一次只改变一个条件；不按是否提到某框架、向量库或消息队列评分。

### 练习路线

入门先练 1–20、36–40、46–49 和 89；应用工程重点练 21–35、56–74、81–94；资深岗位再练 75–80 和 95–100。每轮组合一道机制题、一道失败处理题和一道核心案例。

## 1. LLM 基础与技术选型

<a id="q-1"></a>

#### 1. Transformer 核心组成与工程影响

**题型：** 专项题，P0

##### 题干与约束

解释常见 Decoder-only 语言模型从输入 Token 到输出分布的过程，并说明哪些结构影响推理成本。

##### 答案骨架

1. Token 经 Embedding 和位置相关机制进入多层 Block，最后由输出层产生下一 Token 的 logits。
2. Attention 通过 Q/K/V 建模上下文关系，多头关注不同表示；因果约束防止读取未来 Token。
3. FFN 逐位置变换表示，Residual 与归一化帮助信息和梯度传播；具体顺序依架构而异。
4. Attention、FFN 和 KV Cache 共同影响计算与内存开销，不能仅凭参数量判断延迟。

##### 递进追问

输入长度翻倍时，为什么不能断言总耗时恰好翻倍？

##### 常见失分点

把所有 Transformer 都说成自回归模型；只背模块名称；忽略位置、Mask 和实现差异。

**回答补充：**

1. 先写 Attention(Q,K,V)=softmax(QKᵀ/√dₖ)V，再解释多头的不同投影；Q、K 用于匹配，V 提供聚合内容，直接用 V 替代 K 会改变参数化与匹配空间。
2. MHA 每个查询头有独立 KV，GQA 让一组查询头共享 KV，MLA 以潜变量压缩 KV，具体缓存与解码实现需按模型核实。
3. LayerNorm 对特征减均值再缩放，RMSNorm 按均方根缩放而不减均值；BatchNorm 使用批统计，与序列任务的归一化轴不同。
4. 比较绝对位置、相对位置与 RoPE 的位置表达及长度外推边界。
5. BERT 类侧重双向编码，GPT-2 类侧重因果生成，T5 为编码器—解码器；Decoder-only 的统一生成接口和训练扩展便利不代表其他架构失去适用场景。

#### 2. Token 与可用上下文窗口

**题型：** 专项题，P0

##### 题干与约束

多轮工具任务不断超出上下文限制，如何估算并管理可用窗口？

##### 答案骨架

1. Token 是模型输入输出的基本单位。了解 BPE、WordPiece 与 SentencePiece 等分词算法或工具，但实际计数使用目标模型的 Tokenizer 或供应商能力，中文字符与 Token 没有固定一一对应关系。
2. 统计规则、历史、工具声明、证据、结果与输出预算；部分接口另有输出或推理预算。
3. 先预留生成空间，再按任务优先级选择输入；超限前裁剪、摘要或检索。
4. 监控截断率、任务成功率、输入长度与成本，窗口能容纳不代表能有效利用。

工具返回突然增大十倍，哪些内容应保留，哪些可以转为引用？

##### 常见失分点

只计算用户消息；按字符数精确计费；把标称窗口全部用于输入。

#### 3. Embedding 与文本相似度

**题型：** 专项题，P0

##### 题干与约束

解释文本 Embedding 的用途，以及相似检索为什么不能证明答案相同。

##### 答案骨架

1. 文本编码器把句子或段落映射到向量空间，用于检索、聚类、去重和路由，与内部 Token 表示的使用方式不同。
2. 按模型训练方式选择余弦、内积或距离，确认是否需要归一化，不能任意替换。
3. 相似度不是事实正确概率；否定、时间、数值和主体变化可能改变答案。
4. 固定模型与预处理版本，用领域查询评估；不同模型空间通常不能混用。

##### 递进追问

两个模型输出维度相同，为什么仍不能直接在同一索引里比较？

##### 常见失分点

把维度当质量指标；所有向量都强制归一化；把相似度当置信概率。

#### 4. LLM 生成的 Prefill 与 Decode

**题型：** 专项题，P0

##### 题干与约束

用户反馈“第一段很慢”和“每个字都很慢”，如何解释两类延迟？

##### 答案骨架

1. 常见自回归推理先处理输入完成 Prefill，再迭代 Decode 生成后续 Token。
2. TTFT 包含排队、网络、预处理和 Prefill；TPOT 描述后续 Token 生成间隔。
3. 输入长度、调度与缓存影响首 Token，输出长度与 Decode 速度影响完成时间。
4. Decode 在不少场景受内存带宽制约，实际瓶颈还与模型、硬件和批量有关。
5. 输出上限只限制生成长度，不保证准确长度；截断可能破坏 JSON 或工具参数，需检查结束原因。

##### 递进追问

开启流式后首屏更快但总耗时不变，如何解释？

##### 常见失分点

把流式等同于推理加速；混淆 TTFT 与总耗时；忽略排队。

#### 5. 幻觉、忠实度与拒答

#### 6. 采样参数与可复现性

**题型：** 专项题，P1

##### 题干与约束

相同输入偶尔得到不同结果，Temperature、Top-p、Top-k 和 Seed 能保证什么？

##### 答案骨架

1. Temperature 改变分布锐度，Top-p 按累计概率选候选，Top-k 按数量截断，支持情况依接口而异。
2. 固定 Seed 和低温可减少随机性，不能保证跨版本、调度和计算环境逐字复现。
3. 固定输入、模型与配置，记录依赖结果；稳定格式由契约和校验保障。
4. 业务幂等保存首次有效结果，不能靠再次生成相同文本实现。

##### 递进追问

Temperature 为零仍有差异，应记录哪些版本和输入？

##### 常见失分点

把 Seed 当承诺；认为低温保证正确；只比较文本而忽略业务结果。

##### 面经扩展

- **[AI-064](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-064)** · Temperature、top-p、top-k 分别是什么？不同场景如何设置？

**回答补充：** Temperature 调整 logits 分布，top-k 保留固定数量候选，top-p 保留达到累计概率的候选集合；不同 API 的支持与组合顺序需核实。用同一任务的多次采样评估多样性、正确率与稳定性，不能把低温等同于事实正确。

#### 7. Prompt、RAG 与 Fine-tuning 的取舍

**题型：** 专项题，P0

##### 题干与约束

格式不稳定、私有知识缺失和成本过高同时出现，如何选择手段？

##### 答案骨架

1. 建立基线与错误分类，判断来自行为、知识、模型能力还是系统链路。
2. Prompt 与输出约束适合调整规则、示例与格式；RAG 提供可更新、可追溯的外部知识。
3. Fine-tuning 学习任务行为、格式和领域模式，需要数据、训练与回归投入，知识更新不自动发生。
4. 三者可组合，按收益与维护成本判断次序，不把“先 RAG 后微调”当普适规则。
5. 微调数据需覆盖任务分布并隔离验收集，评估过拟合、遗忘及工具行为回归；权限仍由应用执行。

##### 递进追问

知识完整但工具选择持续错误，为什么加文档可能无效？

##### 常见失分点

用微调代替实时查询；声称任何微调都不影响知识；缺少数据和评测依据。

#### 8. KV Cache 与长上下文

**题型：** 专项题，P1

##### 题干与约束

长对话并发增加后显存不足，KV Cache 的收益与代价是什么？

##### 答案骨架

1. KV Cache 复用已处理 Token 的 Key/Value，减少 Decode 重复计算。
2. 缓存量与层数、KV 头数、头维度、Token 数、并发及数据类型有关。

4. 批处理不意味着任意请求共享 KV；受支持的共同前缀才有额外复用机会。

##### 递进追问

两个请求只有后半段相同，为什么不能直接当共同前缀命中？

##### 常见失分点

把 KV Cache 等同于答案缓存；认为 Batching 自动共享历史；只估权重。

#### 10. 自托管与模型 API 的边界

**题型：** 专项题，P2

#### 13. 结构化输出与业务校验

**题型：** 专项题，P0

##### 答案骨架

#### 14. Function Calling 的执行责任

**题型：** 专项题，P0

##### 题干与约束

解释工具声明到结果回传的过程，模型与应用各负责什么？

##### 答案骨架

1. 应用提供名称、描述与 Schema，模型生成调用建议与参数。
2. 应用解析、验证权限与参数后执行，模型通常不直接执行业务函数。
3. 结果与调用 ID 对应回传；并行建议检查依赖和副作用冲突。

同时建议“查余额”和“扣款”，为什么不应一律并行？

##### 常见失分点

#### 15. SSE 流式输出协议

**题型：** 专项题，P1

##### 题干与约束

##### 答案骨架

#### 21. 企业 RAG 全链路设计

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

十万份持续更新的文档提供带引用问答，峰值每秒 30 个问题，用户权限不同。规模仅作练习假设，需澄清文件大小、更新率与延迟目标。

##### 不可协商约束

- 无权内容不能进入用户可见答案、引用与共享缓存。
- 来源版本和处理状态可追踪，证据不足不编造政策。
- 源文档是内容权威，索引是可重建的派生数据。

##### 关键决策

离线与在线边界；权限与索引协同；检索、重排、生成预算。

##### 答案骨架

1. 接入文档及版本，异步解析、分块、Embedding、建立索引，记录阶段状态与血缘。
2. 在线鉴权、改写、混合召回、重排，组装带定位证据，生成并核验引用。
3. 更新与删除采用幂等事件、版本保护与缓存失效，发布完整版本并暴露新鲜度。
4. 分层评测解析、召回、忠实度与成功，监控积压、撤权延迟、费用和尾延迟。

##### 故障注入

文档撤权但索引未同步；处理完这一故障后，再假设新版本解析失败。分别说明阻止越权、标识缺口与恢复方案。

##### 评价要点

区分内容、权限、索引与答案责任，说明失败承诺及重建验证。

##### 面经扩展

- **[AI-088](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-088)** · 完整介绍 RAG 从文档入库到检索、生成的流程。
- **[AI-234](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-234)** · 设计百万或千万级商品知识库问答系统。

**回答补充：** 百万或千万商品场景先区分商品数、文档数、Chunk 数与向量数，再估计增量更新、索引容量、召回扇出和重排预算。静态说明进入索引，价格与库存由权威接口读取；按实体 ID、版本与权限关联，避免大规模检索质量掩盖事实过期。

#### 36. Agent 与 Workflow 的选择

**题型：** 专项题，P0

##### 题干与约束

一个任务 80% 路径固定、20% 需要判断，如何决定自治程度？

##### 答案骨架

1. Workflow 由应用预定义流程，Agent 由模型在允许范围选择下一动作；实际系统可混合。
2. 固定规则和高风险状态迁移交给确定性流程，开放问题定位与方案探索可引入 Agent。
3. 比较成功率、可测性、成本和维护复杂度，不能因有 LLM 调用就称为 Agent。
4. 自治部分设工具边界、预算、完成标准与人工入口，按实际收益扩大范围。

##### 递进追问

开放路径后来变得稳定，是否应该固化为 Workflow？

##### 常见失分点

把 Agent 当固定工作流的必然升级；只比较灵活性；没有限制自主动作。

#### 38. 任务拆解与完成标准

**题型：** 专项题，P0

##### 题干与约束

用户要求“调研并生成报告”，如何拆成可执行、可验证的任务？

##### 答案骨架

1. 明确报告范围、交付格式、来源要求与完成标准，先消除影响路径的歧义。
2. 按依赖、工具、执行环境与风险拆步骤，独立只读步骤可以并行。
3. 为子任务定义输入、产物、验证器和失败责任；“生成了一段文本”不自动等于完成。
4. 记录计划版本与进度，逐步展开必要细节，避免一次生成庞大但不可执行的计划。

##### 递进追问

两项子任务共享同一前置资料，如何减少重复读取与成本？

##### 常见失分点

只列自然语言清单；无依赖和验收；把规划等同于执行。

##### 面经扩展

- **[AI-020](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-020)** · Modular Agent 如何实现多步规划？
- **[AI-021](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-021)** · 如何做任务拆分？为什么要拆分？如何衡量和提升效果？

**回答补充：** 任务拆分按可验收产物、依赖与权限划界，比较成功率、返工和协调成本。十万词分类先定义标签体系、歧义与多标签规则，做去重、批处理、检查点和抽样标注；可用规则或小模型处理稳定部分，大模型处理困难样本。按可独立验证的批次并行，不按词数机械创建子 Agent。

#### 39. 失败后的重规划

**题型：** 专项题，P1

##### 题干与约束

计划第一步失败，是重试、换方案还是重新规划？

##### 答案骨架

1. 分类为暂时依赖故障、参数错误、能力缺失、授权拒绝或目标不可达。
2. 可恢复故障有界重试，参数错误反馈纠正，缺权限不得通过替代路径绕过。
3. 重规划保留已验证产物、已发生副作用和未决状态，只修改受影响依赖。
4. 记录变更原因，检查新方案预算与完成标准，目标需改变时请求用户决定。

##### 递进追问

第一步已提交付款但后续失败，为什么不能简单从头重规划执行？

##### 常见失分点

任何错误都重跑；丢失已执行事实；通过换工具绕过拒绝。

##### 面经扩展

- **[AI-230](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-230)** · 行程中遇到下雨或用户将两天改成一天时，Agent 如何调整？

**回答补充：** 天气变化与天数缩短分别触发局部替换和全局约束重算；保留用户确认的预算、交通、预订与不可退款事实。计划有版本，受影响步骤及下游重新验证，已发生业务动作必须查询或按规则补偿，不能仅修改自然语言行程。

#### 40. 空转识别与预算终止

**题型：** 专项题，P0

##### 题干与约束

Agent 重复调用同一工具，如何识别无进展并停止？

##### 答案骨架

1. 同时设最大步骤、总时长、费用与单工具失败上限，作为应用层止损边界。
2. 检查规范化动作、参数、观察和产物是否重复，区分正常轮询与无效循环。
3. 用证据增长、子任务完成和错误减少衡量进展，重复不等于必然空转。

##### 递进追问

工具必须轮询十次才能完成，如何避免误判？

##### 常见失分点

只限制轮次；用不同措辞逃过检测；预算耗尽却伪报成功。

#### 41. 短期记忆、长期记忆与业务状态

**题型：** 专项题，P0

##### 题干与约束

对话历史、用户偏好和订单进度应分别存在哪里？

#### 43. 记忆召回与污染防护

**题型：** 专项题，P1

##### 题干与约束

旧任务的错误结论被不断召回，如何阻止自我强化？

#### 44. 多 Agent 编排与任务协议

**题型：** 专项题，P1

##### 题干与约束

研究、写作与审查是否应该交给三个 Agent？

子 Agent 超时但稍后返回，编排器如何避免重复合并结果？

数量越多越好；无协议与责任；没有总预算。

**回答补充：** 中心编排便于统一预算、依赖与验收，但协调方需恢复；分布式协作提高局部自治，同时增加状态一致性与终止难度。信箱可落持久化队列，共享状态用版本更新，事件驱动要处理重复、乱序与关联；消息携带 task_id、父任务、输入版本、结果 Schema 与验收证据。A2A 侧重 Agent 发现与任务交互，MCP 侧重工具和资源接入；协议不自动解决权限、幂等或业务结果核验。

#### 45. 多 Agent 共享资源冲突

**题型：** 专项题，P2

##### 题干与约束

两个 Agent 同时改同一文档或代码库，如何保证结果可审查？

##### 答案骨架

1. 先划分所有权与任务边界，能独立工作时使用隔离工作区和明确输入版本。
2. 修改生成带基线版本的补丁，合并时检测冲突并由指定协调方处理。
3. 共享业务资源使用版本条件更新或适当锁；受保护操作仍需独立授权。
4. 合并后执行整体验证，保留各自产物与审计，不把子任务通过等同于集成通过。

##### 递进追问

两份补丁单独测试通过但组合失败，谁负责发现和恢复？

##### 常见失分点

共享目录任意写；只加锁不定义所有权；无集成验证。

##### 面经扩展

- **[AI-028](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-028)** · 多个 Agent 同时修改同一文件，如何避免冲突？

**回答补充：** 按文件或模块分配所有权，隔离工作区生成带基线版本的补丁；合并方负责冲突消解和组合验证。锁只解决同时写入，不能代替语义冲突检测、完整测试或用户已有修改保护。

#### 46. 工具 Schema 与业务契约

#### 56. 长任务的异步执行与恢复

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

任务执行 2–20 分钟，包含多轮模型调用和可写业务工具。支持一万项在途任务，客户端可断线，Worker 可能随时重启；需进一步明确到达率和完成时间分布。

##### 不可协商约束

- 任务不依赖单个 HTTP/SSE 连接存活。
- 工具副作用不能因进程恢复而盲目重做。
- 用户能查询最终与未知状态，人工修复有记录。

##### 关键决策

Task、Step、Attempt 如何划分；执行权和 Checkpoint 如何配合；任务落库、消息和外部副作用如何收敛。

##### 答案骨架

1. 接入层鉴权、幂等创建 Task 并可靠投递，返回任务 ID 与状态查询入口。
2. Worker 获取有效执行权，记录 Step 和每次 Attempt，固定配置版本并保存中间产物。
3. 外部写操作使用稳定业务幂等键，未知结果先查询；步骤确认后提交进度。
4. 状态与结果独立持久化，事件流用于展示；恢复、取消、审批和修复有显式状态及审计。

##### 故障注入

工具已写成功但 Worker 在提交步骤前宕机。先说明恢复处理，再假设旧 Worker 恢复并与新 Worker 竞争执行。

##### 评价要点

能解释权威事实、执行权与去重责任；不声称消息队列天然保证端到端 exactly-once。

- **[AI-001](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-001)** · 一次 Agent 请求从用户输入到最终回答，完整链路是什么？

**回答补充：** 完整链路为身份与目标确认、上下文组装、模型决策、工具校验执行、结果核验、状态提交与交付。Harness 管理循环、工具、权限、状态、预算和验证；长任务还需队列、持久化、租约、恢复与产物保留，不能让 HTTP 连接或进程内历史承载全部生命周期。

#### 57. Agent 状态机与并发更新

**题型：** 专项题，P0

#### 58. Checkpoint 与步骤提交时机

**题型：** 专项题，P0

##### 题干与约束

##### 答案骨架

1. Checkpoint 表示已验证并可恢复的进度，不是“发出请求”的位置。
2. 先确认产物持久化与步骤结果，再提交进度；同库记录尽量事务化。
3. 外部副作用不能与本地记录原子提交时，先保存操作意图和幂等键，用结果查询收敛。
4. 恢复验证 Checkpoint 引用的产物和版本，避免进度存在但产物丢失。

##### 递进追问

工具成功但 Checkpoint 更新失败，恢复时应从哪里判断？

##### 常见失分点

执行前推进进度；只存步骤号；假设所有写入原子。

- **[AI-032](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-032)** · 运行数天的 Agent 遇到第三方接口报错，如何从断点继续而不重头运行？
- **[AI-033](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-033)** · 如何定制任务调度、状态回退、Checkpoint 与 Trace 回放能力？

**回答补充：** 检查点保存已提交步骤、输入版本、产物引用和未决工具操作；恢复前核对外部事实与执行权。定制调度与回退需保留任务依赖和状态版本；Trace 回放用于诊断，重新执行必须走授权、幂等和副作用核验，不能把日志重放等同于安全重跑。

#### 59. Worker 租约与执行权

**题型：** 专项题，P1

##### 题干与约束

旧 Worker 长暂停后恢复，新 Worker 已接管任务，如何防并行写？

##### 答案骨架

1. 用有过期时间的租约分配执行权，心跳续租与进展监控分开。
2. 分配单调执行代次或 Fencing Token，任务更新检查当前持有者与版本。
3. 资源或执行网关支持时拒绝旧代次操作；仅在任务库加锁无法阻止已发出的外部请求。

心跳正常但步骤十分钟无进展，应续租还是终止？

##### 常见失分点

worker_id 当执行代次；锁过期等于旧执行停止；没有下游边界。

#### 60. 请求、任务与工具幂等

**题型：** 专项题，P0

##### 题干与约束

重复点击、消息重复和工具重试应分别使用什么键？

##### 答案骨架

1. 请求键在租户与操作范围内唯一，同键不同参数拒绝，避免错误复用。
2. Task 去重保证同一请求只建一个逻辑任务，Attempt 可多次但逻辑步骤不变。
3. 工具副作用使用稳定业务键或操作 ID，重试保留它，最终系统负责去重。
4. 保存状态和首次有效结果；生成不可复现时优先复用已存结果，而非重新生成冒充幂等。

##### 递进追问

去重记录过期后旧消息再次投递，如何避免再次产生副作用？

##### 常见失分点

每次重试生成新键；只按消息 ID；没有范围与保存期限。

#### 61. 工具成功但响应丢失

**题型：** 专项题，P0

##### 题干与约束

发送通知请求超时，对方可能已经发送，接下来如何处理？

##### 答案骨架

1. 记录结果未知，保留业务操作 ID，超时不能直接解释成失败。
2. 有幂等与查询能力时查询或携同键重试，区分接收、执行与最终完成。
3. 无此能力时评估重复成本，采用对账、人工核验或限制自动重试。

##### 递进追问

第三方不支持查询也不支持幂等，能承诺绝不重复且绝不丢失吗？

##### 常见失分点

超时立即重发；本地去重当下游去重；没有未知状态。

#### 62. 任务落库与消息可靠投递

**题型：** 专项题，P1

##### 题干与约束

任务写库成功但发 MQ 失败，如何避免永远不执行？

消息发送成功但 Outbox 未标记，重发后如何处理？

##### 常见失分点

库与 MQ 裸双写；宣称 Outbox 消除所有重复；无积压监控。

#### 63. 取消与超时后的副作用

**题型：** 专项题，P0

##### 题干与约束

#### 64. 人工审批与恢复执行

**题型：** 专项题，P0

##### 题干与约束

#### 65. 部分成功与补偿边界

#### 66. 超时、重试与重试放大

**题型：** 专项题，P0

##### 题干与约束

SDK、网关和 Worker 都重试，如何避免一次失败变成数十次调用？

#### 67. 模型与工具限流熔断

#### 70. Webhook 与完成通知

<a id="q-71"></a>

#### 71. 高并发 Agent 容量设计

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

活动期间十万用户在一分钟内提交任务，任务平均调用模型 4 次、工具 6 次。需要先澄清输入输出长度、耗时分布、可排队时间与供应商配额，不能把十万用户直接解释成十万次同时推理。

##### 不可协商约束

- 在有限模型与工具配额下提供明确的接收、排队、拒绝和完成语义。
- 一个租户的突发不能耗尽所有客户资源。
- 缓存、路由与降级不能破坏权限和业务事实。

##### 关键决策

入口与实际调用压力如何换算；哪些任务同步、哪些异步；如何保护尾延迟和内部工具。

##### 答案骨架

1. 估算入口约 1667 请求/秒；按调用次数、Token 和时长推导模型、工具及在途压力，加入重试余量。
2. 短交互可流式同步，长任务持久化后排队；设置接收配额、租户调度与等待上限。
3. 对可复用只读任务启用有权限与版本约束的缓存，按评测路由模型，限制工具并发。
4. 分开测排队、TTFT、完成时间、成功率与费用，验证突发、长任务和恢复流量。

##### 故障注入

供应商可用 TPM 减半，说明限流与排队调整；随后单独加入内部工具 P99 升高，说明隔离和可接受降级。

##### 评价要点

估算能改变设计，不把 MQ 当无限容量，不把 SSE 或异步化当实际吞吐提升保证。

##### 面经扩展

- **[AI-145](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-145)** · Agent 面向 5000–6000 人、每天十几万次请求时如何扩容？

**回答补充：** 把人数、日请求数换算为声明峰均比的任务到达率，再乘模型轮次、Token、工具扇出与重试估压力。并发由到达率和执行时长估计，扩容同时受供应商配额、数据库、检索和慢工具约束；用目标负载和突发验证尾延迟与租户公平。

#### 72. 语义缓存与误命中治理

**题型：** 专项题，P0

##### 题干与约束

“可以报销”和“不可以报销”很相似，如何避免缓存错误复用？

##### 答案骨架

1. 相似检索只提供候选，时间、主体、条件、否定与权限共同决定答案是否等价。
2. 缓存绑定租户、授权范围、上下文、知识和策略版本，副作用结果不按语义重执行。
3. 用近似但不同答案的负例校准阈值，高风险任务禁用或增加精确校验。
4. 监控误命中、质量和每成功任务成本，知识更新、撤权与删除触发失效。

##### 递进追问

命中率上升但投诉增加，为什么不能继续降低阈值？

##### 常见失分点

只有相似度和 TTL；共享个性化答案；缓存代替授权检查。

<a id="q-73"></a>

#### 73. 精确缓存与前缀缓存

**题型：** 专项题，P1

##### 题干与约束

结果缓存、语义缓存与 Prefix Caching 分别复用什么？

##### 答案骨架

1. 精确结果缓存复用完整响应，键包含会影响结果的输入、版本、权限和上下文。
2. 语义缓存对近似问题复用答案，需要额外等价性与误命中评测。
3. 前缀缓存复用共同输入前缀的计算或 KV，不返回旧答案；vLLM APC 主要减少 Prefill 而非 Decode 时间。
4. 根据服务实现检查缓存键、隔离和失效，缓存命中不意味着无计费或永远保留。

##### 递进追问

固定 Prompt 前放随机时间戳，会怎样影响共同前缀复用？

##### 常见失分点

三个缓存混为一谈；前缀缓存认为能减少所有生成时间；忽略隔离。

##### 面经扩展

- **[AI-086](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-086)** · Prompt Caching 是什么？
- **[AI-087](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-087)** · Prompt Cache 为什么能提升调用效率？如何提高缓存命中率？

**回答补充：** Prompt Cache 复用支持的相同前缀计算，通常减少 Prefill 成本与延迟，不缓存最终答案，也不直接加速每个 Decode Token。稳定规则与工具声明放前部，动态内容后置；结合模型、供应商隔离、最低长度和计费规则验证实际命中收益，不为命中率复用无权或过期上下文。

#### 74. 模型路由与质量门禁

**题型：** 专项题，P0

##### 题干与约束

简单任务用小模型，如何判断哪些任务必须升级？

##### 答案骨架

1. 用任务类型、输入长度、工具复杂度、语言、风险和数据约束建立规则或分类路由。
2. 在切片样本上验证小模型可接受范围，路由器误判也进入评测。
3. 低质量、校验失败或能力不足时可升级，限制重复尝试与总费用。
4. 记录路由原因、模型、版本和结果，不能把供应商失败自动当小模型可替代。

##### 递进追问

路由器本身调用大模型，如何判断是否仍然节省成本？

##### 常见失分点

只按问题长度；模型自报“简单”作依据；无升级和质量门禁。

#### 75. LLM Serving 性能优化

**题型：** 专项题，P2

##### 题干与约束

自托管模型吞吐低，如何选择 Batching、量化和缓存？

##### 答案骨架

1. 先区分排队、Prefill、Decode 与通信瓶颈，测 TTFT、TPOT、吞吐和显存。
2. Continuous Batching 动态调度不同阶段请求，提高利用率，也需控制长短请求干扰。
3. 分页 KV 管理、前缀复用、INT8/FP8/INT4 等受支持量化和适用的投机解码按目标负载比较收益与质量。
4. 调整并行方式、上下文和批预算，压测必须满足延迟 SLO，不能只报最大 Tokens/s。

##### 递进追问

大批量提高吞吐但首 Token 变慢，应如何选配置？

##### 常见失分点

GPU 利用率高就认为用户体验好；量化无损假设；无真实长度分布。

**回答补充：**

1. vLLM 常见机制包括分页 KV、连续批处理与前缀复用，调度需兼顾 Prefill/Decode、公平、抢占与尾延迟；具体支持随版本核实。
2. FlashAttention 通过分块和片上存储减少 HBM 读写，避免物化完整注意力矩阵，不把它等同于近似注意力；PD 分离隔离两阶段负载，但需付出 KV 传输与调度成本，AF 一词必须先核对原文含义及实现边界。
3. 量化按权重、激活与 KV 分别讨论；per-tensor、per-channel、per-group 的细度取决于分组轴与组大小，不能一概声称 group 最细。
4. minmax 容易受离群值影响，percentile 以裁剪换动态范围，KL/MSE 校准分别按分布差异与重构误差选阈值。
5. SmoothQuant 通过等价缩放平衡权重与激活难度，AWQ 关注激活感知的权重量化，GPTQ 利用近似二阶信息逐步降低权重量化误差。
6. FP8/FP4 的收益依赖硬件、内核与精度验收；反量化开销可被访存节省抵消，也可能导致小批次或特定 Shape 退化。
7. 固定模型、长度、批量和硬件测质量、TTFT、TPOT 与吞吐，用 Profiling 和 Roofline 判断访存、计算或调度瓶颈。

#### 76. GPU 显存与并发估算

**题型：** 专项题，P2

##### 题干与约束

70B 模型能支持多少长对话并发，如何给出有边界的估算？

##### 答案骨架

1. 先确认精度、模型结构、GPU 数量、并行方式、上下文和输出长度，不能只凭型号给固定数字。
2. 权重初估为参数量乘每参数字节，额外加入量化元数据、运行缓冲与内存余量。
3. 普通 KV 粗估为 `2 × 层数 × KV 头数 × 头维度 × Token 数 × 字节数`，再考虑并发和具体分片。
4. 根据剩余显存求候选并发，再用真实负载验证碎片、调度与延迟，特殊结构需另建模型。

##### 递进追问

使用 GQA 后，为什么不能继续用 Query 头数估 KV 大小？

##### 常见失分点

只算权重；忽略长度与余量；显存放得下等于满足延迟。

##### 面经扩展

- **[AI-195](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-195)** · 估算 Qwen3-8B 推理所需显存。
- **[AI-223](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-223)** · 长轮次推理显存异常增长、OOM 或随机崩溃，如何排查？

**回答补充：** Qwen3-8B 按名义 8B 参数粗估，BF16/FP16 权重约 16 GB（十进制），实际以检查点参数量为准，另加 KV、缓冲与余量；量化还需缩放元数据和内核工作区。多轮显存增长先区分有效 Token 增长、活跃任务、保留张量、KV 未释放、分配器预留与碎片；按轮次采样已分配／已保留显存，结合 Profile 和最小复现定位，不能把所有增长都归为内存泄漏。

#### 77. 背压、队列与公平调度

**题型：** 专项题，P1

##### 题干与约束

任务到达快于处理速度，如何防队列持续膨胀？

##### 答案骨架

高优先级任务持续到达，低优先级任务如何避免永久等待？

##### 常见失分点

无限队列；只扩 Worker 不看供应商配额；只有队列长度没有等待指标。

#### 78. 成本拆解与预算控制

**题型：** 专项题，P1

##### 题干与约束

流量不变但费用翻倍，如何诊断和限制成本？

##### 答案骨架

1. 拆分输入、输出、缓存相关计费、Embedding、Rerank、工具、存储与裁判费用。
2. 按任务、租户和版本比较轮次、长度、重试、路由与误命中，而非只看总 Token。
3. 执行前估算或预留预算，执行中逐步扣减和调整；预留与最终结算幂等并核对账单。
4. 压缩、缓存、路由和允许延迟的批处理都以质量门禁为前提，优化每成功任务成本。

##### 常见失分点

#### 79. 多供应商 Fallback

**题型：** 专项题，P1

##### 题干与约束

##### 常见失分点

所有模型可互换；两个输出直接拼接；跨供应商绕过数据约束。

#### 80. AI Gateway 架构

**题型：** 核心案例，P2，45 分钟

##### 目标与规模假设

统一接入三家模型供应商，为 100 个应用提供路由、配额和计量，峰值每秒 500 次模型请求。需澄清流式占比、Token 分布、租户和服务等级。

##### 不可协商约束

- 密钥与租户信息不进入模型可见上下文。
- 路由符合数据策略，计费和重试可归因。
- 网关失败有明确降级，不能形成无保护的全量旁路。

##### 关键决策

公共协议与供应商能力差异如何表达；配额一致性如何取舍；控制面失效时执行面如何工作。

##### 答案骨架

1. 数据面鉴权、策略检查、准入、适配与流式转发，控制面管理模型、凭据和配置版本。
2. 路由依据能力、质量、成本和故障；租户配额区分请求、Token、并发及金额。
3. 多副本网关使用可用的预算与限流机制，明确强一致校验和短时本地额度的取舍。
4. 记录逻辑请求与尝试，核对用量；配置故障使用有期限的已验证快照，敏感策略失效时拒绝。
5. 可复用请求采用精确或语义缓存，键包含权限与版本；审计与脱敏按策略执行，流式转发需明确审核和断线边界。

##### 故障注入

配额存储不可用，说明可继续与必须拒绝的请求；随后单独加入供应商流式中断，说明尝试和计量处理。

##### 评价要点

处理适配差异、预算与可用性，而非只画反向代理；不把 Fallback 当无条件放行。

**回答补充：** 统一请求、响应、错误分类与用量结构，同时保留供应商原始错误和能力差异。逻辑请求与多次尝试分开计量，重试有 Deadline、预算和幂等保护；流式事件、取消和部分输出必须有明确公共语义。

#### 83. Agent 轨迹与任务成功评测

**题型：** 专项题，P0

##### 题干与约束

##### 答案骨架

1. 分开评估最终结果、过程安全、效率和可恢复性，结果正确不能抵消非法行为。

3. 容许多个有效轨迹，不强制唯一调用顺序；依赖与必须验证的步骤保留约束。
4. 在可重置环境多次运行，统计成功率、步骤、费用和方差，避免残留状态污染实验。

#### 84. LLM-as-a-Judge 校准

**题型：** 专项题，P1

##### 题干与约束

模型裁判与人工不一致，能否直接用于发布门禁？

##### 答案骨架

1. 定义评分准则、标签和可见证据，固定裁判模型与 Prompt；裁判也需要评测。
2. 对比独立人工标签，检查位置、长度、风格与自偏好，换序或重复评分发现不稳。
3. 无效标签不能静默当负例，报告有效样本和无效数；按误判代价检查混淆矩阵。

大多数样本都合格，总准确率很高为何仍可能漏掉严重失败？

##### 常见失分点

#### 86. Agent 故障定位与止血

**题型：** 专项题，P1

##### 题干与约束

耗时从 5 秒变成 30 秒，错误率也上升，如何排查？

##### 答案骨架

1. 确认受影响任务、租户和时间，比较近期模型、Prompt、索引、工具与调度变更。
2. 分解排队、模型、检索、工具、重试和步骤数，定位首次偏离，而非只看最终错误。
3. 延迟先查等待、TTFT/TPOT 与工具尾延迟，错误先查证据、Schema、权限和状态。
4. 按证据回滚、限流或暂停高风险动作，随后核验副作用、重放可恢复任务并复盘。

##### 递进追问

模型延迟不变但工具调用数翻倍，应该先扩 GPU 吗？

##### 常见失分点

全部归为模型幻觉；先全量重跑；止血后不核对业务事实。

#### 87. AI 服务 SLI、SLO 与告警

**题型：** 专项题，P1

#### 88. 模型、Prompt 与索引发布

**题型：** 专项题，P1

##### 题干与约束

同时存在模型、Prompt、工具与索引版本，如何发布和回滚？

##### 答案骨架

1. 定义可兼容的配置组合，任务记录所用模型、Prompt、工具契约和索引版本。
2. 单元、契约与任务回归通过后影子或小流量灰度，安全和关键业务切片设门禁。

## 9. 安全、隐私与多租户

<a id="q-89"></a>

#### 89. Prompt Injection 防御

**题型：** 专项题，P0

##### 题干与约束

网页或文档要求 Agent 忽略用户限制并发送内部资料，如何防护？

##### 答案骨架

1. 标明用户指令与外部内容的信任边界，网页、文档、图片文字和工具结果均可携带注入。
2. 模型识别与内容检测降低风险，但工具执行必须由独立授权和数据策略控制。
3. 限制读写与网络权限，把敏感操作绑定用户批准的对象和参数，必要时隔离读写任务。
4. 测试间接注入、跨工具传播和数据外泄，审计拒绝与误杀，不声称单一 Prompt 能彻底防御。

##### 递进追问

恶意文档自称“企业管理员已批准”，执行层如何判断？

##### 常见失分点

只写“忽略恶意指令”；模型自己授权；只测用户直接输入攻击。

<a id="q-90"></a>

#### 90. SSRF 与数据外泄防护

**题型：** 专项题，P0

##### 题干与约束

Agent 可访问 URL 和上传文件，如何防止访问内网或把数据发送到外部？

##### 答案骨架

1. 限制协议、端口、目标域与地址范围，阻止未授权环回、私网、元数据地址及相关 IPv6 地址。
2. 检查解析、实际连接与每次重定向，防 DNS Rebinding；以出口代理或网络策略补充应用校验。
3. 上传、邮件、回调与浏览动作执行数据出口授权，允许目标不代表允许发送所有数据。
4. 回调验签与防重放，记录来源、目标、敏感字段和批准范围，不能只校验 URL 字符串。

##### 递进追问

白名单域重定向到 `169.254.169.254`，哪一层应拒绝？

##### 常见失分点

只查域名；只禁一个 IP；网络允许就默认数据可外传。

#### 91. PII 与模型数据最小化

**题型：** 专项题，P0

##### 题干与约束

Agent 需要处理客户资料，如何减少不必要的数据暴露？

##### 答案骨架

1. 先定义任务所需字段，只向模型发送必要数据，凭据和完整账户资料留在受控执行层。
2. 脱敏或假名化后保留受保护映射，必要时由工具恢复字段，注意关联数据仍可能识别主体。
3. 分别制定模型供应商、工具、日志、记忆和产物的访问及留存策略。
4. 数据训练使用、地域、合同和删除能力按实际政策与约定核实，不凭“企业版”名称推断。

##### 递进追问

电话号码已遮盖但姓名和地址完整，是否已充分去标识化？

##### 常见失分点

脱敏一次认为全链路安全；映射公开；供应商数据处理政策未经核实。

#### 92. Guardrails 与误杀治理

**题型：** 专项题，P0

##### 题干与约束

审核既要拦截危险输出，也不能大面积阻断正常业务，如何设计？

#### 93. 多租户隔离与资源公平

**题型：** 专项题，P1

##### 题干与约束

1000 家企业共享平台，如何保证数据、执行和费用不串租户？

##### 答案骨架

1. 租户身份来自可信认证上下文，数据、任务、索引、缓存、记忆与产物访问均绑定它。
2. 查询范围和工具凭据不能由模型自由指定，高敏感租户按需要升级独立存储或执行环境。
3. 隔离密钥、沙箱、出口与管理权限，观测和客服后台同样实施租户边界。
4. 配额、排队、费用归因和负载测试覆盖热点租户，避免大客户造成邻居噪声。

##### 递进追问

共享缓存键漏了 tenant_id，但模型回答看起来正常，如何发现？

##### 常见失分点

只在表里加租户字段；相信模型传入租户；后台和日志无隔离。

#### 94. 对话、记忆与派生数据删除

**题型：** 专项题，P1

##### 题干与约束

用户要求删除对话和记忆，如何防止摘要、向量或旧备份再次恢复它们？

##### 答案骨架

1. 用数据血缘枚举源记录、摘要、向量、缓存、产物、日志与供应商副本。
2. 先阻止读取和召回，再可靠传播删除，记录范围、期限与处理状态，法定保留另行说明。
3. 删除事件有版本保护，重建索引和恢复备份时重放删除清单，防止数据复活。
4. 按备份和供应商能力明确实际删除窗口及限制，完成后核验可见路径与审计证据。

在线已删但离线重建使用一周前快照，如何避免再次写回？

##### 常见失分点

只删会话表；所有系统即时物理删除的无依据承诺；忽略备份。

## 10. 端到端系统设计案例

<a id="q-95"></a>

#### 95. 企业知识助手

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

两万员工查询制度、项目文档与结构化业务资料。文档持续更新且权限细分，交互希望几秒内得到首段有依据内容；需澄清最终完成目标与知识更新时限。

##### 不可协商约束

- 文档回答带可访问引用，业务实时状态来自权威接口。
- 不向无权用户暴露内容、存在性或历史缓存。
- 没有证据时明确缺口，不用通用知识假装内部制度。

##### 关键决策

知识问答与业务查询如何路由；权限撤销如何生效；多轮指代与来源冲突如何处理。与第 21 题相比，本题重点是产品承诺和多来源融合。

##### 答案骨架

1. 入口建立用户身份与会话，判断查知识、查实时事实还是需要澄清。
2. 文档走带权限的 RAG，结构化事实走只读工具，保留来源时间与适用范围。
3. 汇总时核验引用、冲突与字段，敏感场景交付前复核，结果与流式事件可恢复。
4. 按部门、语言、无答案和撤权场景评测，监控新鲜度、解决率、延迟与费用。

##### 故障注入

用户转部门后旧缓存仍存在，说明处理；再假设制度文档与实时 API 冲突，说明权威归属。

##### 评价要点

根据事实类型选路径，说明权限和时效，而非所有数据都塞向量库。

##### 面经扩展

- **[AI-235](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-235)** · Text-to-SQL 如何实现？如何提高准确率？

**回答补充：** Text-to-SQL 先检索授权 Schema、字段含义与业务口径，再生成受约束 SQL，做语法、表列权限、只读与资源校验。使用最小权限数据库身份与数据库侧行列策略执行，限制行数、超时与费用；仅允许 SELECT 文本不足以防危险函数或越权。以真实执行结果、口径一致性和拒答质量评测，歧义先澄清。

<a id="q-96"></a>

#### 96. 客服与工单 Agent

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

日均十万会话，提供政策解答、工单创建和进度查询，可转人工。用户身份与可执行动作依渠道不同，需要明确自动处理范围和转人工响应要求。

##### 不可协商约束

- 不编造退款、赔付和处理完成承诺。
- 工单创建幂等，用户资料最小化。
- 人工接管后明确执行权，自动 Agent 不继续冲突操作。

##### 关键决策

固定服务流程与模型判断边界；转人工触发与上下文交接；工具超时后的事实核验。

##### 答案骨架

1. 鉴权和意图识别后进入适当流程，政策来自可追溯知识，状态来自业务工具。
2. 高风险动作通过业务规则与审批，创建工具有幂等键和查询入口。
3. 转人工传递用户目标、证据、已做动作和未决状态，记录接管与恢复条件。
4. 评测解决率、错误承诺、重复工单、人工负担及费用，投诉不能只归为回答风格。

##### 故障注入

工单创建超时但实际已成功，说明重试策略；随后客户再次提问，说明如何保持身份与同一事项关联。

##### 评价要点

定义业务承诺和人机交接，避免用兜底文案掩盖未知状态。

<a id="q-97"></a>

#### 97. Coding Agent 平台

**题型：** 核心案例，P1，45 分钟

##### 目标与规模假设

支持百个团队并行处理代码任务，每项任务可运行 30 分钟，交付补丁和验证记录。需澄清仓库大小、依赖下载、执行环境与是否允许提交、推送和部署。

##### 不可协商约束

- 保留用户已有修改，跨任务工作区与凭据隔离。
- 仓库文本和工具输出不能扩大任务授权。
- 结果包含真实验证证据，失败或未运行检查明确标注。

##### 关键决策

工作区生命周期、补丁集成责任、测试执行与审查门禁；读写和网络权限如何约束。

##### 答案骨架

1. 固定基线、任务目标与项目约束，分配隔离工作区和受限执行环境。
2. 检索代码、规划变更、生成补丁，子任务按文件与责任分工，共享修改需协调。
3. 执行相关测试与构建，保存命令和产物，审查检查需求、回归与测试是否有效。
4. 集成前重验基线与冲突，外部写操作按授权执行，清理环境时保留可恢复产物。

##### 故障注入

任务测试通过但目标分支随后改变，说明集成验证；再假设两个任务修改同一函数，说明冲突责任。

##### 评价要点

区分补丁生成、验证、审查与发布，不把自主编码解释成无限权限。

##### 面经扩展

- **[AI-149](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-149)** · Coding Agent 作为团队工具时，如何处理文件、命令权限、安全与审计？

**回答补充：** 团队平台按仓库、任务和用户委托授予路径与命令权限，区分生成补丁、执行测试、提交和部署；审计关联输入版本、补丁、授权及命令结果。隔离凭据与工作区，保留用户已有变更，敏感外部写入绑定具体审批对象。

<a id="q-98"></a>

#### 98. 研究与报告 Agent

**题型：** 核心案例，P1，45 分钟

##### 目标与规模假设

针对一个用户问题读取最多 200 个来源，生成带引用的报告，允许执行 20 分钟。明确研究范围、时间边界、来源类型与预算，不能用来源数量代替质量。

##### 不可协商约束

- 区分事实、推断和未验证结论，引用可追溯。
- 外部资料不触发未经授权的动作或数据上传。
- 超时仍交付可用产物及明确缺口，不伪装完整覆盖。

##### 关键决策

研究问题如何拆解；来源去重和可信度如何管理；并行检索收益与最终整合责任。

##### 答案骨架

1. 明确子问题与证据要求，分配可并行的只读任务，限制检索跳数与 Token。
2. 保存来源、读取时间、版本与定位，识别转载、冲突和失效内容。
3. 按主张组织证据，再生成报告和引用，重要结论由核验步骤检查。
4. 持久化进度与产物，结束条件包括覆盖、预算和进展；评测准确、完整与引用支持。

##### 故障注入

重要来源不可访问，说明报告缺口；随后单独加入某网页中的恶意上传指令，说明阻断路径。

##### 评价要点

说明证据质量、终止和产物恢复，不把抓取成功率当研究成功率。

**回答补充：** 将漫剧作为有阶段验收的创作工作流：场景理解、脚本、分镜、角色设定、片段生成、剪辑与交付各有版本和产物。角色一致性保存角色设定、参考资产、服装与场景约束，Seed 不能单独保证跨片段一致；评估身份、动作、叙事连续性与用户反馈。节点返工仅重算受影响下游，保留通过版本和预算；此变体复用本题的分解、产物与恢复机制，视觉一致性另需专门评测。

#### 99. 有副作用的业务操作 Agent

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

Agent 根据用户请求创建订单、申请退款或发送通知，每秒接收 100 项操作请求。需要澄清可自动执行的范围、审批规则与第三方幂等能力。

##### 不可协商约束

- 模型建议不是业务授权，金额与状态由权威系统检查。
- 重复请求不能重复创建同一业务操作，未知结果可查询与核验。
- 不可逆动作不能被描述成已自动回滚。

##### 关键决策

哪些步骤使用确定性流程；审批绑定与状态变化如何处理；外部操作记录与本地进度如何一致。

##### 答案骨架

1. 解析意图后生成动作提案，验证身份、对象、金额、前置状态与权限。
2. 所需审批绑定参数与版本，执行前重验；不满足条件返回新提案或拒绝。
3. 保存操作意图与稳定业务键，通过权威工具执行，结果未知时查询或对账。
4. 分开记录任务与业务结果，通知异步可靠投递，取消和补偿按业务可逆性处理。

##### 故障注入

退款已成功但响应丢失，说明收敛；再假设审批后可退金额变化，说明执行前检查。

##### 评价要点

覆盖授权、幂等、未知结果与人工恢复，不以模型输出决定交易终态。

**回答补充：** 行程规划先澄清出发地、日期、人数、偏好和预算口径，查询天气、交通、营业时间与价格后检查时间和地理可行性；预算 2000 元只作为用户约束，不编造实时价格。对“好吃的”等模糊需求优先追问会改变推荐的条件，允许明确假设。查询推荐与预订付款分开授权，失败后保留已确认事项并按真实业务状态恢复。

#### 100. 多租户 Agent 平台

**题型：** 核心案例，P2，45 分钟

##### 目标与规模假设

向 1000 家企业开放 Agent 配置、知识接入、工具和异步执行，租户有不同数据策略与服务等级。需澄清峰值、长任务比例、供应商、私有部署和灾难恢复要求。

##### 不可协商约束

- 身份、知识、缓存、记忆、工具凭据和产物按租户授权。
- 配置发布可追溯，运行任务不被未审核的新配置悄然改变。
- 预算、执行隔离和删除要求贯穿平台，不由模型自行遵守。

##### 关键决策

控制面与执行面边界；共享与专属资源划分；平台能力如何复用而不跨越租户策略。

##### 答案骨架

1. 控制面管理身份、配置、版本、工具注册与策略，执行面承载队列、Worker、沙箱与状态。
2. AI Gateway 管模型路由与计量，知识与工具访问保留用户委托范围，敏感租户可用专属资源。
3. 任务固定兼容配置组合，采用分层配额与公平调度；故障域隔离，控制面不可用有有限快照策略。
4. 建设数据血缘、删除、评测发布、Trace 和恢复入口，按租户验证服务目标与成本归因。
5. 从最小可运营平台演进，达到隔离、容量或组织瓶颈再拆能力，不默认每个框都做独立服务。

##### 故障注入

一个租户造成积压，说明公平调度；随后单独加入错误工具配置已灰度，说明停止、回滚与在途处理。

##### 评价要点

把前面机制落实到平台边界、故障域和运营责任，而非只列框架与中间件。

##### 面经扩展

- **[AI-014](../../../wxquare-private/tools/interview-results/AI与Agent面试题汇总.md#ai-014)** · 为什么把 Agent 做成云端服务，而不是本地 Harness 或 CLI？

**回答补充：** 云端服务适合集中权限、资源调度、任务恢复与团队协作，本地 Harness 或 CLI 适合贴近开发环境、低启动成本与本地数据处理；比较网络依赖、数据边界、沙箱、运维成本与离线能力。混合部署可让控制面管理配置和任务、受控执行器靠近代码或私有数据，仍须明确凭据、产物与执行权归属。
